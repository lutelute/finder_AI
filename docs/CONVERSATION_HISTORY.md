# ここで何をしたか — 過去の会話を思い出す

「claudeで前回の続き」ボタンは、戻れることは教えてくれるが、**何の続きなのか**は教えてくれない。押すまで分からない。3日空けば、押しても分からない。

このフォルダで過去にAIと何をしたのかを、押す前に読めるようにする。

## FinderAIは何も溜めない

claudeもcodexも、自分の会話を既に全部ディスクに書いている。FinderAIが同じものをもう一度集める理由はない。**読むだけ**にする。

| | 置き場所 | 現在の量 |
|---|---|---|
| claude | `~/.claude/projects/<パスをハイフン化>/<sessionId>.jsonl` | このフォルダぶんで170MB / 全体3.1GB |
| codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | 277本 / 全体323MB |

ターミナル出力を自前で持たない今の方針（`TerminalSessionRecord.swift`）は、そのまま変わらない。読む先が他人のファイルになるだけで、増えるものが無い。

## 読む順番

安い順に3段。上で足りたら下は見ない。

**1. `sessions-index.json` があればそれだけ読む**

claudeがプロジェクトごとに置いていることがある。806バイトで、欲しいものが全部入っている。

```json
{
  "sessionId": "9a572b73-…",
  "firstPrompt": "https://github.com/lutelute/test_NN.git これも論文作って。フルペーパー",
  "summary": "Grokking Paper: Clone, Write, Convert to 2-Column IEEJ PDF",
  "messageCount": 25,
  "modified": "2026-01-19T19:43:54.545Z",
  "gitBranch": "",
  "projectPath": "/Users/shigenoburyuto/Documents/論文執筆自動化test"
}
```

ただし205プロジェクト中44しか持っていない。**あてにはできるが、頼りにはできない。**

**2. 無ければ `*.jsonl` の先頭だけ読む**

`type == "user"` の行から、最初の実発話を1本。先頭120行で打ち切る。実測は次のとおり。

```
08/19 16:23     201KB  右または下に出るターミナルからのAIで，過去にclaudeやcodex…
08/15 12:03     164KB  このプロジェクトの現状を読み取って、以下を簡潔にまとめて…
08/15 11:25   54141KB  グルーピングの見た目があまり好みじゃない。codexとclaude…
08/11 11:38   36644KB  finderAIで読み込みが遅い場合がる。例えばgithubのディレクトリ…

6件ぶんで読んだ量: 18KB / 所要 2ms
```

54MBのファイルからも18KBしか読まない。ファイルの大きさは効かない。

**3. codexは1行目にcwdがある**

`session_meta` が先頭行に来る。277本を1行ずつ舐めて0.8秒。フォルダ単位の索引が無いので全部見るしかないが、一度作った対応表はrolloutの数とmtimeが変わるまで使い回せる。

```json
{"type":"session_meta","payload":{"cwd":"/Users/…/finder_AI", "session_id":"019fc650-…"}}
```

`~/.codex/session_index.jsonl` にはcwdが無い（`id` / `thread_name` / `updated_at` だけ）ので使わない。

## フォルダ名から逆算してはいけない

claudeのディレクトリ名は、元のパスに戻せない。

```
/Users/shigenoburyuto/Documents/論文執筆自動化test
  ↓
-Users-shigenoburyuto-Documents--------test
```

`/` も `_` も `.` も、非ASCIIの1文字も、区別なくハイフン1個になる。`tool_dev_SGNB` が `tool-dev-SGNB` になるのと同じ潰れ方で、`論文執筆自動化`（7文字）は7個のハイフンとして残る。**別のフォルダが同じ名前に化けうる。**

だから名前は当たりをつけるためだけに使い、確定は必ず実パスで照合する。

1. パスをハイフン化した名前でディレクトリを引く
2. 見つかったら `sessions-index.json` の `originalPath`、無ければ最新jsonlの `cwd` を読む
3. 標準化したパスが一致したときだけ、そのフォルダの履歴として採用する

照合に読むのは1ファイルの先頭1行だけなので、この一手間はほぼ無料。

## 増える保存は1行だけ

見出しを引き当てるたびにファイルを開き直すのは無駄なので、台帳に持たせる。

```swift
public var lastSummary: String?      // 直近の見出し 1行（60字で切る）
public var lastSummaryAt: Date?      // その見出しを取った時刻
```

`TerminalSessionRecord` には既に `lastTranscriptPath` という同じ性格のフィールドがある。増えるのは1セッションあたり200バイト前後で、100セッション溜めても20KB。ログ本体（170MB）に対して誤差でしかない。

一覧を開いたときの5件は、キャッシュせずその場で読む。2msなので置いておく意味がない。

案Aで作った。ただし畳まない。島を畳めるようにしたときと同じで、**既定は開いたまま**にしてある——隠れたメニューの中より、見えているほうがいい。

出るのはセッションがまだ無いとき、つまり開始ボタンが並んでいる画面。押す前に読めることに意味があるので、そこでいい。

claudeとcodexは混ぜて新しい順に並べる。ただし**どちらで話した回かは行の印に残す**（claudeは`sparkles`、codexは`< >`、色も種類ごとのもの）。ここが消えると、続きに戻る相手を間違える。

## 行を押したら戻る

行はボタンで、押すとその回から再開する。claudeは `--resume <sessionId>`、codexは `resume <SESSION_ID>`（どちらもUUIDを受ける。実測: claude 2.0系 / codex 0.147.0）。

戻り先の決め方は2通りあるので、型で分けた。

```swift
public enum ConversationResume: Equatable, Sendable {
    case latest              // ボタン: --continue / resume --last
    case session(id: String) // 履歴の行: --resume <id> / resume <id>
}
```

以前は `Bool` が層を貫いていて「戻るか否か」しか運べなかった。`nil` が新規、`.latest` がボタン、`.session(id:)` が履歴の行。呼び出し側のラベル（`resumesConversation:`）は変えていないので、差分は型のところだけで済んでいる。

指した会話がもう無くても壊れない。既存の `resumeFallbackScript` がそのまま効いて、断りを1行出してから新しい会話へ落ちる。

**これで「続き」が最新1件に固定されなくなった。** 3日前の回にも戻れる。

## 作らないもの

- **自前のログ収集** — 二重に持つ理由がない
- **全文検索** — 見出しが並べば目で足りる。欲しくなってから考える
- **AIによる要約生成** — 金も時間もかかる。`firstPrompt` は本人が書いた言葉なので、要約より思い出しやすい
